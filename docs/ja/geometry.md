# ジオメトリ・メッシュ調査

## はじめに

RenderEyeMCP はグラフィクスドローコールが消費・生成するジオメトリを調査するための
6 つのツールを提供します。調査は RenderDoc GUI に既にロードされているキャプチャに対し
て行われるため、ライブアプリケーションや新たなキャプチャ取得は不要です。

ツールは 2 つの視点から構成されています。

- **入力ジオメトリ** — アプリケーションが供給するもの: 頂点バッファ、インデックス
  バッファ、入力レイアウト、ドロー引数。
- **出力ジオメトリ** — 頂点シェーダーが生成するもの: RenderDoc のリプレイ機能で
  取得するクリップ空間の位置とシェーダー出力。

この 2 つを比較することで次のような疑問に答えられます。

- 「バッファ内の頂点位置は正しいか？」
- 「頂点バッファのレイアウトと頂点シェーダーの入力シグネチャは一致しているか？」
- 「頂点シェーダーはジオメトリを正しく変換しているか？」
- 「このドローコールは何プリミティブを処理し、縮退三角形はいくつあるか？」

---

## 前提条件

- RenderEyeMCP 拡張機能を有効にした状態で RenderDoc が起動していること。
- RenderDoc GUI にキャプチャ (`.rdc` ファイル) がロードされていること。
- 現在選択されているイベント (または明示的に指定した `event_id`) がグラフィクスの
  ドローコールであること。状態変更・コピー・コンピュートイベントは対象外です。
- ジオメトリツールを呼び出す前に `get_current_capture` で動作確認してください。

---

## 利用可能なツール

| ツール | 役割 | 読み取り専用 |
|---|---|---|
| `get_draw_geometry_info` | ドロー引数とジオメトリ構成 | はい |
| `get_vertex_input_layout` | 頂点属性とバッファバインディング | はい |
| `get_mesh_indices` | 指定範囲のインデックスをデコード | はい |
| `get_mesh_vertices` | 指定した頂点属性をデコード | はい |
| `get_post_vs_geometry` | 頂点シェーダー後の位置と出力 | いいえ† |
| `get_mesh_statistics` | ジオメトリ統計: バウンディングボックス・縮退・無効値 | はい |

† `get_post_vs_geometry` は頂点シェーダー出力をキャプチャするためにリプレイパスを
実行するため `readOnlyHint: false` となっています。ロード済みキャプチャや GUI で
選択されているイベントは変更されません。

---

## サポートするドロータイプ

全ツールはインデックスあり・なしドローの両方をサポートします。インスタンス化ドローは
関連するパラメーター (`instance_id` / `instance`) で制御できます。

| ドロータイプ | サポート |
|---|---|
| 非インデックス (`Draw`) | はい |
| インデックス (`DrawIndexed`) | はい |
| インスタンス化 (`DrawInstanced`, `DrawIndexedInstanced`) | はい (範囲制限あり) |
| インダイレクト (`DrawIndirect`, `DrawIndexedIndirect`) | メタデータのみ |
| コンピュート・コピー・ブリット | 対象外 |

インダイレクトドローについては RenderDoc が報告するメタデータ (頂点数・インデックス数)
を返しますが、インダイレクト引数バッファの展開は行いません。

---

## サポートするプリミティブトポロジー

RenderDoc が返す文字列をそのまま報告します。

`triangle_list`, `triangle_strip`, `triangle_fan`, `line_list`, `line_strip`,
`point_list`, `patch_list` および隣接バリアント。

縮退プリミティブの検出 (`get_mesh_statistics`) は `triangle_list` のみに対応して
います。それ以外のトポロジーでは `degenerate_primitives: null` を返します。

---

## ツールリファレンス

### `get_draw_geometry_info`

対象ドローコールのジオメトリ構成を返します: ドロータイプ、トポロジー、頂点数・
インデックス数・インスタンス数、オフセット、頂点バッファバインディング、
インデックスバッファバインディング。

**パラメーター**

| パラメーター | 型 | デフォルト | 説明 |
|---|---|---|---|
| `event_id` | int | `0` | `0` のとき GUI で選択中のイベントを使用 |
| `instance_id` | string | `""` | MCP インスタンス識別子 (マルチエージェント用) |

**主なレスポンスフィールド**

| フィールド | 意味 |
|---|---|
| `draw_type` | `indexed`, `non_indexed`, `indirect` のいずれか |
| `topology` | プリミティブトポロジー文字列 |
| `index_count` | 処理するインデックス数 (インデックスドロー) |
| `vertex_count` | 頂点数 (非インデックスドロー) |
| `instance_count` | インスタンス数 |
| `first_index` | インデックスバッファの開始位置 |
| `base_vertex` | 各インデックスに加算する符号付きオフセット |
| `first_instance` | 最初のインスタンスインデックス |
| `vertex_buffers` | バインドされた VB スロットのリスト (リソース ID・オフセット・ストライド) |
| `index_buffer` | バインドされた IB のリソース ID・オフセット・フォーマット |

---

### `get_vertex_input_layout`

パイプラインステートで宣言された頂点入力属性とバッファバインディングを返します。
各属性レコードは RenderDoc の `VertexInputAttribute` に対応しています。

**パラメーター**

| パラメーター | 型 | デフォルト | 説明 |
|---|---|---|---|
| `event_id` | int | `0` | `0` のとき GUI で選択中のイベントを使用 |
| `instance_id` | string | `""` | MCP インスタンス識別子 |

**属性ごとの主なレスポンスフィールド**

| フィールド | 意味 |
|---|---|
| `name` | 属性名・セマンティック名 (例: `POSITION`, `NORMAL`) |
| `location` | シェーダー入力レジスタ番号 |
| `comp_type` | コンポーネント型: `Float`, `UNorm`, `SNorm`, `UInt`, `SInt` など |
| `comp_count` | コンポーネント数 (1–4) |
| `comp_byte_width` | 1 コンポーネントあたりのバイト数 |
| `vertex_buffer` | VB バインディングスロット |
| `byte_offset` | 頂点要素内のバイトオフセット |
| `per_instance` | `true` のときインスタンスごとの属性 |
| `instance_rate` | インスタンスステップレートまたは除数 |

---

### `get_mesh_indices`

バインドされたインデックスバッファから指定範囲のインデックス値をデコードします。
生のインデックス値を返し、`base_vertex` は別途報告されます (デコード値には加算しません)。

**パラメーター**

| パラメーター | 型 | デフォルト | 説明 |
|---|---|---|---|
| `event_id` | int | `0` | `0` のとき GUI で選択中のイベントを使用 |
| `first_index` | int | `0` | インデックス配列内の開始位置 |
| `count` | int | `100` | 取得するインデックス数 (最大 1 000) |
| `instance_id` | string | `""` | MCP インスタンス識別子 |

非インデックスドローではインデックスバッファが存在しない旨のエラーを返します。

---

### `get_mesh_vertices`

バインドされた頂点バッファから指定した範囲の頂点属性値をデコードします。
インスタンスごとの属性は頂点インデックスでアドレス指定するため現在スキップされます。

**パラメーター**

| パラメーター | 型 | デフォルト | 説明 |
|---|---|---|---|
| `event_id` | int | `0` | `0` のとき GUI で選択中のイベントを使用 |
| `first_vertex` | int | `0` | 開始頂点インデックス |
| `count` | int | `10` | 取得する頂点数 (最大 100) |
| `attributes` | list[string] | `null` | 取得する属性名のリスト; `null` のとき全属性を返す |
| `instance_id` | string | `""` | MCP インスタンス識別子 |

**頂点ごとの主なレスポンスフィールド**

| フィールド | 意味 |
|---|---|
| `vertex_id` | 頂点インデックス (`first_vertex + n`) |
| `attributes` | 属性名 → デコード済みコンポーネントリスト のマップ |

---

### `get_post_vs_geometry`

RenderDoc の `GetPostVSData` API を使って頂点シェーダー後のジオメトリを取得します。
この API はドローコールをリプレイして頂点シェーダー出力を記録するため、GPU と CPU の
コストが GPU パフォーマンスカウンター収集 1 回分程度かかります。

**パラメーター**

| パラメーター | 型 | デフォルト | 説明 |
|---|---|---|---|
| `event_id` | int | `0` | `0` のとき GUI で選択中のイベントを使用 |
| `instance` | int | `0` | インスタンスインデックス |
| `view` | int | `0` | ビューインデックス (マルチビューレンダリング用) |
| `stage` | string | `"vs_out"` | `vs_in`, `vs_out`, `gs_out` のいずれか |
| `max_vertices` | int | `50` | 出力頂点の最大数 (最大 100) |
| `instance_id` | string | `""` | MCP インスタンス識別子 |

**頂点ごとの主なレスポンスフィールド**

| フィールド | 意味 |
|---|---|
| `vertex_id` | 出力頂点インデックス |
| `clip_pos` | クリップ空間の位置 `[x, y, z, w]` |
| `ndc_pos` | NDC 位置 `[x/w, y/w, z/w]` (`w ≈ 0` のとき省略) |
| `outputs` | その他のシェーダー出力属性 (VS 出力シグネチャから取得) |

Post-VS の位置は**クリップ空間**であり、ワールド空間ではありません。NDC 変換は標準的
な透視除算を前提としており、アクティブな射影行列の文脈で解釈してください。

---

### `get_mesh_statistics`

最大 `max_vertices` 個の頂点位置と (インデックスドローの場合は) 限定されたインデックス
セットを読み取りジオメトリ統計を計算します。

**パラメーター**

| パラメーター | 型 | デフォルト | 説明 |
|---|---|---|---|
| `event_id` | int | `0` | `0` のとき GUI で選択中のイベントを使用 |
| `max_vertices` | int | `200` | バウンズ・妥当性確認に使うサンプル頂点数 (最大 500) |
| `instance_id` | string | `""` | MCP インスタンス識別子 |

**主なレスポンスフィールド**

| フィールド | 意味 |
|---|---|
| `vertex_count` | ドローが宣言した総頂点数 |
| `index_count` | 総インデックス数 (インデックスドロー) |
| `instance_count` | インスタンス数 |
| `topology` | プリミティブトポロジー |
| `sampled` | 読み取り頂点数が総数より少ない場合 `true` |
| `bounding_box` | サンプルした POSITION 値の `{min: [x,y,z], max: [x,y,z]}` |
| `nan_inf_count` | NaN または無限大のコンポーネント数 |
| `degenerate_primitives` | 縮退三角形数 (triangle_list のみ; それ以外は `null`) |

---

## 座標空間

| 空間 | 発生場所 |
|---|---|
| オブジェクト / ローカル空間 | 変換前の頂点バッファ位置 |
| ビュー / ワールド空間 | シェーダー内の中間計算 (直接参照不可) |
| クリップ空間 | `get_post_vs_geometry` の `clip_pos` |
| NDC | `ndc_pos` = clip / w (ツールが導出) |

頂点バッファの位置と Post-VS クリップ空間の位置を同一視しないでください。
座標空間とスケールが異なります。

---

## インスタンス化の動作

`get_draw_geometry_info` と `get_mesh_statistics` は集計値 (総インスタンス数・
総頂点数) を報告します。特定のインスタンスを調べる場合:

- `get_post_vs_geometry`: `instance` パラメーターを指定する。
- `get_mesh_vertices`: インスタンスごとの属性は現在スキップされるため、
  頂点ごとの属性のみがデコードされる。
- `get_mesh_indices`: インデックスはインスタンス間で共有されるため、
  インスタンスごとのフィルタリングはなし。

---

## GPU パフォーマンスとの相関

ジオメトリ調査結果は Phase 13 のパフォーマンス測定と組み合わせられます。
ジオメトリツールが GPU カウンター収集を自動実行することはありません。

推奨ワークフロー:

1. `collect_gpu_counters` でタイミングとパイプライン統計カウンターを収集する。
2. `get_counter_values` または `get_pipeline_statistics` で結果を取得する。
3. `get_performance_summary` で高コストなドローコールを特定する。
4. `get_draw_geometry_info` と `get_mesh_statistics` でジオメトリを調べる。
5. 頂点変換が疑わしい場合のみ `get_post_vs_geometry` を呼び出す。

## 既知の制限事項

- **インスタンスごとの頂点属性** — `get_mesh_vertices` はインスタンスごとの属性を
  スキップします。`get_draw_geometry_info` でバインディングを確認し、
  `get_vertex_input_layout` でオフセットを特定してください。
- **インダイレクトドロー** — インデックス数・頂点数は RenderDoc が公開する値を
  報告します; インダイレクト引数バッファの展開は行いません。
- **ジオメトリ / メッシュ / タスクシェーダー** — VS と GS 以降のステージは対象外
  です。`stage: "gs_out"` を使うにはジオメトリシェーダーがアクティブである必要が
  あります。
- **縮退検出** — `triangle_list` のみ対応。Strip と Fan トポロジーは `null` を返します。
- **サンプル統計** — `get_mesh_statistics` は最大 `max_vertices` 個を読み取ります。
  大きなメッシュではバウンディングボックスと無効値カウントはサンプルのみを対象と
  します。
- **Post-VS のリプレイコスト** — `get_post_vs_geometry` はドローをリプレイします。
  大きなメッシュでは `max_vertices` を小さく設定してデータ転送量を抑えてください。
- **フォーマットサポート** — 半精度 (float16) の頂点属性はデコードされず、
  該当コンポーネントは `null` として返されます。
