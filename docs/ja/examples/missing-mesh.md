# シナリオ G1 — メッシュが表示されない

## 問題

レンダリング結果にオブジェクトが表示されないが、キャプチャ内にそのドローコールは
存在しています。頂点データが無効なのか、変換後の位置がビューフラスタムの外にある
のかを調査します。

## 準備

1. RenderEyeMCP 拡張機能を有効にした状態で RenderDoc が起動していること。
2. キャプチャがロードされていること。
3. 表示されないオブジェクトのドローコールを選択 (または特定) する。

## プロンプト例

**クイック調査:**
> 現在選択されているドローコールのジオメトリを調査してください。頂点バッファと
> インデックスバッファ、入力レイアウト、頂点シェーダー後の位置を確認し、オブジェクト
> が表示されない原因となりそうな不審な値を特定してください。

**詳細な調査:**
> イベント 712 のドローコールが視覚的な出力を生成していません。ジオメトリを徹底的に
> 調査してください: ドロータイプとインデックス/頂点数がゼロでないことを確認し、頂点
> バッファがバインドされているか検証し、最初の10頂点の位置を読んですべてゼロかNaN値が
> ないか確認し、全頂点のNaN/Inf統計を確認し、最初の20頂点のPost-VSクリップ位置を取得
> してください。見つかった根拠から最も可能性の高い原因を特定してください。

## 調査内容

- ドロータイプ(indexed/non-indexed/indirect)、インデックス数、頂点数、インスタンス数 — ゼロカウントはジオメトリが送信されていないことを意味する
- 頂点バッファがバインドされているか、インデックスドローではインデックスバッファが存在するか
- 頂点入力レイアウト: POSITIONが存在し有効なスロットにバインドされているか、コンポーネント型とバイトオフセットが頂点バッファストライドと一致するか
- オブジェクト空間の頂点位置のサンプル: すべてゼロか、NaN/Infを含むか、スケールが妥当か
- メッシュ全体のジオメトリ統計: NaN/Inf数とバウンディングボックス(全位置がNaNの場合はnull)
- 頂点シェーダー後の位置: クリップ空間とNDC位置。特にNDC x/yが[-1,1]内にあるかとw > 0かどうか

## 期待される結果

メッシュが表示されない最も一般的な原因:

- 頂点/インデックス数がゼロ → ジオメトリが送信されていない(CPU側のバグ)
- 頂点バッファが未バインド → 頂点をフェッチできない
- 位置がすべてゼロ → VBがアップロードされていないかクリアされた
- NaN/Inf位置 → VBに無効データが含まれている
- NDC位置が[-1,1]外 → 変換行列が間違っている

## 結果の解釈

**診断フローチャート:**

```
頂点/インデックス数がゼロ → ジオメトリが送信されていない(CPU側のバグ)
頂点バッファが未バインド  → ドローコール前にVBが未設定

頂点位置がすべてゼロ → VB未アップロード/クリアされた
頂点位置がNaN/Inf  → VBに無効データが含まれている
頂点位置が妥当     → Post-VSを確認

Post-VS NDCが[-1,1]外 → 変換行列が間違っている
Post-VS w ≤ 0          → カメラ後方または射影行列が縮退
Post-VS NDCが範囲内    → ジオメトリは可視; ラスタライザ/カリングを確認
```

頂点バッファの位置(オブジェクト空間)とPost-VSクリップ位置を比較することで、
シェーダーステップなしに変換チェーンを観察できます。

## 制限事項

- Post-VSジオメトリの取得はドローコールをリプレイします。大きなメッシュでは
  コストを抑えるために `max_vertices` を小さく(10〜20)設定してください。
- 頂点バッファの値は変換前(オブジェクト空間)です。クリップ空間の Post-VS 位置と
  直接比較しないでください。
- インダイレクトドローはメタデータを報告しますが、実際の頂点数は実行時に決まります。
  バッファが読み取り可能であれば NaN 検出は機能します。
