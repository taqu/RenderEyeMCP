# シナリオ D1 — ピクセルの色が間違っている

## 問題

画面上のあるピクセルが間違った色を表示しています。そのピクセルに最後に書き込んだ
ドローコールを見つけ、なぜ期待通りの結果と異なるのかを調査します。

## 準備

1. RenderEyeMCP 拡張機能を有効にした状態で RenderDoc が起動していること。
2. キャプチャがロードされていること。
3. 問題のあるピクセルのおおよその画面座標がわかっていること。

## プロンプト例

**クイック調査:**
> ピクセル (512, 384) が白になるべきところ暗い赤になっています。どのドローコールが
> 原因で、シェーダーがどんな色を出力したかを見つけてください。

**詳細な調査:**
> ピクセル (512, 384) が白になるべきところ暗い赤を表示しています。ピクセル履歴を使って
> このピクセルに触れた全ドローを確認してください。通過・棄却の別、シェーダーが出力した
> 色、各Eventの前後のPixel値など、全変更を表示してください。ピクセルに最後に書き込んだ
> Eventを特定し、その後に正しい色を出力したはずだが棄却されたEventがあるかどうか説明
> してください。

**フォローアップ (任意):**
> 暗い赤を書き込んだEventのPixel Shaderをデバッグして、なぜ白ではなくその色を
> 出力したか調べてください。

## 調査内容

- 指定座標のピクセル履歴: 全変更、通過・棄却したEvent、棄却理由
- ピクセルに最後に書き込んだEventとその書き込み色を特定する
- 後続のEventが正しい色を出力したが棄却された場合、その理由(深度テスト、ステンシルテスト、Shader discardなど)を確認する
- 棄却理由が深度関連の場合、棄却されたDrawと誤った色を書き込んだDrawの深度パイプラインステートを比較する
- 必要なら、誤った色を出力したDrawのPixel Shaderをステップ実行してライティング/Textureロジックを調査する

## 期待される結果

ピクセル履歴は全変更をEvent順で一覧します。典型的な誤色バグ: イベント88が暗い赤を書き込んで通過し、
イベント120が白を出力したが深度テストで棄却された。白フラグメントが深度競争に負けたため、ピクセルは
暗い赤を表示しています。

## 結果の解釈

- **最後に変更したEvent**が、現在画面に表示されている出力のドローです。
- ピクセル履歴に正しい出力が存在するが棄却されている場合、バグはPixel Shaderのロジックではなく
  深度/ステンシルステート、描画順序、またはブレンドにあります。
- 最後に変更したEvent自体が誤った色を出力している場合、そのShaderを直接調査してください。
- `rejection_reason: depth_test`と正しいShader出力の組み合わせは、深度ステートまたは描画順序の
  バグを強く示唆します。
- ピクセル履歴はGPUリプレイを実行します。多数のピクセルでループして呼び出すことは避けてください。

## 制限事項

- ピクセル履歴は GPU リプレイを実行します。多くのピクセルでループして呼び出すことは
  避けてください。
- `max_modifications` は最大 200 です。非常にオーバードローが多いシーンでは増やしてください。
- ピクセル履歴の利用可能性はグラフィクス API によって異なります。
  [高度なデバッグ](../advanced-debugging.md#グラフィクス-api-とシェーダーサポート)を参照してください。
