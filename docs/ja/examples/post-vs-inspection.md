# シナリオ G3 — 頂点変換の調査

## 問題

オブジェクトが間違った位置に表示されていたり、変換後に歪んでいたり、ビューフラスタム
の端で予期しないクリッピングが発生しています。入力位置 (オブジェクト空間) と
頂点シェーダー後の位置 (クリップ空間) の両方を調べて変換を追跡します。

## 準備

1. RenderEyeMCP 拡張機能を有効にした状態で RenderDoc が起動していること。
2. キャプチャがロードされていること。`get_current_capture` で確認してください。
3. RenderDoc でドローコールを選択する。

## プロンプト例

> このメッシュの入力位置と Post-VS 位置を調べてください。変換後の頂点がクリップ空間
> の可視領域の外にあるかどうかを確認し、関連する変換定数も調べてください。

---

## 調査ワークフロー

### 1. キャプチャのロードを確認する

```json
{ "tool": "get_current_capture" }
```

### 2. ジオメトリ構成を取得する

```json
{ "tool": "get_draw_geometry_info" }
```

`event_id`、`topology`、`index_count` / `vertex_count`、`instance_count` を
メモします。

例 (説明用):

```json
{
  "event_id": 520,
  "draw_type": "indexed",
  "topology": "triangle_list",
  "index_count": 720,
  "instance_count": 1,
  "base_vertex": 0
}
```

### 3. 入力位置 (オブジェクト空間) を読む

```json
{
  "tool": "get_mesh_vertices",
  "first_vertex": 0,
  "count": 10,
  "attributes": ["POSITION"]
}
```

例 (説明用 — 単位球):

```json
{
  "vertices": [
    { "vertex_id": 0, "attributes": { "POSITION": [ 0.000,  1.000,  0.000] } },
    { "vertex_id": 1, "attributes": { "POSITION": [ 0.866,  0.500,  0.000] } },
    { "vertex_id": 2, "attributes": { "POSITION": [ 0.866, -0.500,  0.000] } },
    { "vertex_id": 3, "attributes": { "POSITION": [ 0.000, -1.000,  0.000] } }
  ]
}
```

半径 1 の単位球です。モデル空間にあり、`[-1, 1]` 内の絶対値は正常です。

### 4. Post-VS ジオメトリを取得する (クリップ空間)

```json
{
  "tool": "get_post_vs_geometry",
  "stage": "vs_out",
  "max_vertices": 10
}
```

例 (説明用 — 距離 5 の透視投影):

```json
{
  "vertices": [
    { "vertex_id": 0,
      "clip_pos": [ 0.000,  1.732,  4.900,  5.000],
      "ndc_pos":  [ 0.000,  0.346,  0.980],
      "outputs": {} },
    { "vertex_id": 1,
      "clip_pos": [ 1.500,  0.866,  4.900,  5.000],
      "ndc_pos":  [ 0.300,  0.173,  0.980],
      "outputs": {} },
    { "vertex_id": 2,
      "clip_pos": [ 1.500, -0.866,  4.900,  5.000],
      "ndc_pos":  [ 0.300, -0.173,  0.980],
      "outputs": {} },
    { "vertex_id": 3,
      "clip_pos": [ 0.000, -1.732,  4.900,  5.000],
      "ndc_pos":  [ 0.000, -0.346,  0.980],
      "outputs": {} }
  ]
}
```

すべての NDC 値が `[-1, 1]` 内にあり、`w = 5.0 > 0` です。球は正しく投影されて
います。

### 5. 変換が間違っている場合の例

代わりに次のようなレスポンスが返された場合:

```json
{
  "vertices": [
    { "vertex_id": 0, "clip_pos": [   0.0, 1732.0, 4900.0, 5000.0],
      "ndc_pos":      [   0.0,  346.4,  980.0] },
    { "vertex_id": 1, "clip_pos": [1500.0,  866.0, 4900.0, 5000.0],
      "ndc_pos":      [ 300.0,  173.2,  980.0] }
  ]
}
```

NDC `x` = 300、`y` = 346 は `[-1, 1]` から桁違いに外れています。オブジェクトは
シーンに存在 (有限のクリップ位置、`w > 0`) していますが完全に画面外です。モデル
トランスフォーム、ビュー行列、または射影行列が間違っています。

### 6. 頂点シェーダーの定数バッファを調べる

```json
{ "tool": "get_current_shaders" }
```

頂点シェーダーと MVP 行列が格納されている定数バッファスロットを特定します。

```json
{ "tool": "get_resource_info", "resource_id": "<cbuffer_resource_id>" }
```

定数バッファの最初の 64 バイト (4×4 float32 = 64 バイト) を読んで行列を調べます。
よくある間違いは、初期化時に 1 度だけ設定してカメラに追従して更新されない MVP 行列
です。

### 7. W の処理を確認する

`clip_pos[3]` (w) がゼロに近いまたは負の頂点に特に注意してください。

```json
{ "vertex_id": 5, "clip_pos": [0.1, 0.2, 0.0, 0.0], "ndc_pos": null }
```

`ndc_pos: null` は `w ≈ 0` を意味します。ゼロ除算を避けるためにツールは透視除算を
スキップします。`w ≈ 0` の頂点が多数ある場合、カメラのニアプレーンの設定が間違って
いるか、射影行列に縮退した値があります。

### 8. ジオメトリ統計で Post-VS 位置を比較する

オブジェクト空間のバウンディングボックス情報を取得します。

```json
{ "tool": "get_mesh_statistics", "max_vertices": 200 }
```

オブジェクト空間のバウンディングボックスとオブジェクトの期待されるワールド位置を
比較します。オブジェクトがワールド位置 `(100, 0, 50)` にあるべきで、POSITION の
バウンディングボックスが `[-1, 1]` (単位球) であれば、スケールは頂点シェーダーの
変換にあり、オブジェクト空間データ自体は正しいことになります。

---

## 座標空間まとめ

| データソース | 座標空間 | 期待される範囲 |
|---|---|---|
| `get_mesh_vertices` POSITION | オブジェクト / モデル空間 | メッシュスケールに依存 |
| `get_post_vs_geometry` `clip_pos` | クリップ空間 (同次座標) | 有限; 可視なら `w > 0` |
| `get_post_vs_geometry` `ndc_pos` | NDC (透視除算後) | 画面内なら各軸 `[-1, 1]` |

---

## よくある変換バグ

| NDC の観察 | 考えられる原因 |
|---|---|
| 全値が >> 1 または << -1 | 射影行列が欠落または間違っている |
| 全値が ≈ 0 | 変換後にオブジェクトが原点にある; ビュー行列が間違っている |
| 全頂点で `w ≤ 0` | オブジェクトがカメラ後方; ビューまたはモデルトランスフォームが間違っている |
| 1 軸だけ間違っている | 行列アップロード時の行/列順序が間違っている |
| 特定インスタンスだけ画面外 | インスタンスごとのトランスフォームバッファが更新されていない |

---

## 制限事項

- `get_post_vs_geometry` はドローリプレイを実行します。変換の診断には代表的な
  サンプルで十分なため `max_vertices` を小さく (10–20) 設定してください。
- ここでは VS 出力ステージ (`vs_out`) のみ示しています。ジオメトリシェーダーを
  使うドローでは `gs_out` も利用できます。
- `ndc_pos` はツールが `[x/w, y/w, z/w]` として導出します。RenderDoc が直接
  提供するものではないため、非標準の射影行列の場合はクリップ値で検証してください。
