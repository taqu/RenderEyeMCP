# シナリオ G3 — 頂点変換の調査

## 問題

オブジェクトが間違った位置に表示されていたり、変換後に歪んでいたり、ビューフラスタム
の端で予期しないクリッピングが発生しています。入力位置 (オブジェクト空間) と
頂点シェーダー後の位置 (クリップ空間) の両方を調べて変換を追跡します。

## 準備

1. RenderEyeMCP 拡張機能を有効にした状態で RenderDoc が起動していること。
2. キャプチャがロードされていること。
3. RenderDoc でドローコールを選択する。

## プロンプト例

**クイック調査:**
> このメッシュの入力位置と Post-VS 位置を調べてください。変換後の頂点がクリップ空間
> の可視領域の外にあるかどうかを確認し、関連する変換定数も調べてください。

**詳細な調査:**
> 選択中のメッシュが画面上の間違った位置に表示されています。オブジェクト空間の最初の
> 10頂点位置とクリップ空間の最初の10頂点のPost-VS位置を読んでください。NDC値が[-1,1]内
> にあるか、wが正かを報告してください。オブジェクトが画面外の場合、どの軸が極端な値を
> 示しているか特定し、MVPまたはView-Projection行列を含むConstant Bufferに想定外の値が
> ないか確認してください。

## 調査内容

- ジオメトリ構成: ドロータイプ、インデックス数、頂点数
- オブジェクト空間の入力頂点位置のサンプル — 変換前の生の位置
- 同じ頂点のPost-VS位置: クリップ空間(x, y, z, w)と導出されたNDC座標
- w ≤ 0の頂点がないか(カメラ後方または射影行列が縮退)
- NDC x/yが[-1,1]外にあるか、どれくらい外れているか
- 画面外の位置が見つかった場合、MVPまたはView-Projection行列を含む頂点シェーダーのConstant Buffer

## 期待される結果

有効なオンスクリーン三角形は:
- 全頂点で `w > 0`
- NDC `x` と `y` が `[-1, 1]` 内
- NDC `z` が `[0, 1]` (D3D) または `[-1, 1]` (GL/Vulkan) 内

| NDC の観察 | 考えられる原因 |
|---|---|
| 全値が >> 1 または << -1 | 射影行列が欠落または間違っている |
| 全値が ≈ 0 | 変換後にオブジェクトが原点にある; ビュー行列が間違っている |
| 全頂点で `w ≤ 0` | オブジェクトがカメラ後方; ビューまたはモデルトランスフォームが間違っている |
| 1 軸だけ間違っている | 行列アップロード時の行/列順序が間違っている |
| 特定インスタンスだけ画面外 | インスタンスごとのトランスフォームバッファが更新されていない |

## 結果の解釈

- 妥当な範囲のオブジェクト空間位置と極端なNDC値の組み合わせは、頂点データの破損ではなく
  間違ったView/Projection行列を示します。
- NDC `x` = 300はモデルがクリップ中心から数百ユニット離れた位置にあることを意味します。
  初期化時に一度だけ設定されてカメラに追従して更新されていないMVP行列が原因の可能性があります。
- w ≈ 0の頂点が多数ある場合、カメラのニアプレーンの設定が間違っているか、射影行列に縮退した
  値があります。
- Post-VSジオメトリの取得はドローリプレイを実行します。変換の診断には代表的なサンプルで十分なため
  `max_vertices`を小さく(10〜20)設定してください。

## 制限事項

- Post-VSジオメトリの取得はドローリプレイを実行します。変換の診断には代表的なサンプルで
  十分なため `max_vertices` を小さく(10〜20)設定してください。
- ここではVS出力ステージ(`vs_out`)のみ示しています。ジオメトリシェーダーを使うドローでは
  `gs_out`も利用できます。
- `ndc_pos` はツールが `[x/w, y/w, z/w]` として導出します。RenderDoc が直接提供するものでは
  ないため、非標準の射影行列の場合はクリップ値で検証してください。
