# シナリオ D3 — 深度テスト棄却

## 問題

オブジェクトが他のすべてのものより前面にあるべきなのに表示されていません。
ピクセル履歴ではフラグメントは存在していますが、常に深度テストで棄却されています。

## 準備

1. RenderEyeMCP 拡張機能を有効にした状態で RenderDoc が起動していること。
2. キャプチャがロードされていること。
3. 表示されるべきオブジェクトが現れるはずのピクセル座標がわかっていること。

## プロンプト例

**クイック調査:**
> ピクセル (960, 540) の UI オーバーレイが表示されていません。ピクセル履歴では
> そのドローコールがフラグメントを生成していますが、すべて棄却されています。
> 原因を調べてください。

**詳細な調査:**
> ピクセル (960, 540) に白い UI オーバーレイが表示されるべきですが暗いままです。
> このピクセルに触れた全フラグメントをピクセル履歴で確認してください。棄却された
> フラグメントを生成しているドロー、棄却理由、シェーダーが出力するはずだった色を
> 特定してください。次に棄却されたドローと最後に正常に書き込んだドローのパイプライン
> ステートを比較し、深度設定に着目してください。

**フォローアップ (任意):**
> ピクセル (980, 540) でも同じピクセル履歴の確認を行い、オーバーレイ全体で同じ
> パターンが繰り返されるか確認してください。

## 調査内容

- 該当座標のピクセル履歴 — どのドローコールがそのピクセルに触れ、通過・失敗したか
- 棄却されたフラグメントの棄却理由(深度テスト、ステンシルテスト、shader discardなど)と、通過した場合にシェーダーが出力するはずだった色
- フラグメントが棄却されたドローの深度/ステンシルパイプラインステート — 特に深度テストが有効か、深度比較関数、深度書き込みが有効か
- 棄却されたドローの深度規約と、そのピクセルのバッファにすでに書かれている深度値との比較

## 期待される結果

ピクセル履歴は変更の連鎖を示します。UIオーバーレイのバグでは、最後のシーンジオメトリドロー
(例: イベント305)が深度を正しく書き込み、オーバーレイドロー(例: イベント420)が正しいシェーダー
出力を生成するものの、z = 1.0(遠平面)でレンダリングされているのに対しシーンがすでにそのピクセルに
z = 0.82を書き込み深度関数がLESSのため、フラグメントが棄却されているという結果が期待されます。

## 結果の解釈

| `rejection_reason` | 意味 | よくある原因 |
|---|---|---|
| `depth_test` | 深度比較が失敗 | 間違った深度関数、不正な z 値、早すぎる深度書き込み |
| `stencil_test` | ステンシル比較が失敗 | ステンシルマスクの不一致、間違った参照値 |
| `shader_discard` | シェーダーが `discard` / `clip` を呼び出した | アルファテスト、範囲外 UV、明示的なカリング |
| `backface_cull` | 裏面が除去された | 間違った巻き順、反転した法線 |
| `scissor` | シザー矩形の外側 | シザー矩形の設定ミス |
| `sample_mask` | MSAA サンプルマスクで除外 | MSAA 設定の不一致 |
| `unknown` | 理由が特定できない | 他のパイプラインステージを確認 |

UIオーバーレイが`depth_test`で棄却されている場合: UIドローコールパスの
`depth_enable = false`(または`depth_func = ALWAYS`)を設定することで修正できます。

## 制限事項

- ピクセル履歴は GPU リプレイベースです。多くのピクセルでタイトなループで呼び出すことは
  避けてください。
- 深度棄却が期待通り (正しいオクルージョン) の場合は、`passed: true` を使用してピクセルに
  実際に書き込んだ最後のフラグメントを見つけてください。
